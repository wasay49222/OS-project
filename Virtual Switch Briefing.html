02

What a switch does

Background
  1. Learn: the source MAC came in on port 1, so the switch writes "0A is on port 1" in its MAC table.
  2. Look up: it looks for the destination MAC in the same table.
  3. Forward or flood: found, so it sends to that one port. Not found, or a broadcast, so it sends to every port except the one the frame came from.
03

Our switch is a group of processes

The big picture
  • Host: a client process you also write, for testing. Our test hosts replace yours when we mark.
  • Switch: the server, listening on a TCP port. Each accepted connection is one switch port.
  • swctl: a second client, for the admin. It uses a UNIX domain socket (a socket that is a file path, local only) and reads counters from shared memory, as in Lab 07.
04

A frame, byte by byte

Tier 1 · item 1

Three traps

  • Partial reads. TCP is a byte stream. One read() can return 5 bytes of a frame, or one and a half frames.
  • Byte order. length and vlan travel in network byte order: convert with ntohs and htons.
  • Struct padding. A C struct with these fields has sizeof 18, not 17. Read into a byte buffer and unpack it.
/* returns n, 0 if the peer closed, -1 on error */
ssize_t read_full(int fd, void *buf, size_t n)
{
    size_t got = 0;
    while (got < n) {
        ssize_t r = read(fd, (char *)buf + got, n - got);
        if (r == 0) return 0;
        if (r < 0) {
            if (errno == EINTR) continue;
            return -1;
        }
        got += r;
    }
    return got;
}
05

Inside the switch: the threads

Tier 1 · items 2 to 4

The receiver never writes to another host's socket. It only puts the frame on queues. Each port's own sender thread does the write(). That one rule is what keeps a slow host from hurting the others.

07

The bounded queue: condition variables

New this project

A sender with an empty queue must sleep, not spin. A condition variable lets a thread sleep until another thread says "something changed". It always goes with a mutex.

/* receiver: never waits */
pthread_mutex_lock(&q->lock);
if (q->count == q->cap) {
    q->dropped++;            /* full: drop */
    pthread_mutex_unlock(&q->lock);
    return;
}
q->item[q->tail] = f;
q->tail = (q->tail + 1) % q->cap;
q->count++;
pthread_cond_signal(&q->not_empty);
pthread_mutex_unlock(&q->lock);
/* sender: sleeps while empty */
pthread_mutex_lock(&q->lock);
while (q->count == 0 && !q->closing)
    pthread_cond_wait(&q->not_empty, &q->lock);
if (q->closing) { ... }       /* port shut down */
f = q->item[q->head];
q->head = (q->head + 1) % q->cap;
q->count--;
pthread_mutex_unlock(&q->lock);
write_full(sock, f, ...);       /* outside the lock */
  • pthread_cond_wait unlocks the mutex while it sleeps and locks it again before it returns.
  • Always while, never if: the thread can wake up when nothing changed.
  • Never hold a lock during a write() to a socket. The circular buffer arithmetic is the same as Lab 07, section 3.4.
08

A broadcast is one frame, shared

Tier 1 · item 3
  • The count changes from several threads, so changing it and checking for zero must happen together, under a mutex.
  • Set the count to the number of queues the frame really went into. A dropped copy (queue full) must not count.
  • Get this wrong and you get a use-after-free or a double free. Valgrind finds both; I will show it.
09

The MAC table: one lock per bucket

Tier 1 · item 4
  • Aging: a thread removes entries not seen for T seconds.
  • Host moved: a known MAC arrives on a new port: update it and log "MAC moved".
  • At most K entries: when full, remove the least recently used one.
  • Port security: more than M MACs on one port means an attack (MAC flooding). Shut that port down.
10

A limit on ports: a counting semaphore

Tier 1 · item 5

The semaphore starts at the number of ports. Each new host takes one (sem_wait), each host that leaves gives one back (sem_post). This is the gate from Lab 08, Topic 9.

New here: a timeout. If no port frees up in time, the host gets a "switch full" reply and is disconnected.

struct timespec t;
clock_gettime(CLOCK_REALTIME, &t);
t.tv_sec += 5;                  /* wait at most 5 s */
if (sem_timedwait(&free_ports, &t) == -1) {
    if (errno == ETIMEDOUT)
        send_switch_full(sock);
    close(sock);
}
11

Scheduling inside the switch

Tier 2 · items 6 and 7

Weighted round robin plus aging

This is Lab 04 again, but inside a real program. Add aging: a low frame that has waited too long (for example 200 ms) is sent next, whatever the weights say.

Rate limit: a token bucket

Each port may send X frames per second. A timer thread adds tokens; sending one frame spends one. A sender with no tokens waits with pthread_cond_timedwait, never sleep() and never a spin loop.

12

VLANs, a trunk port, and mirroring

Tier 2 · items 8 and 9
  • VLAN rule: forwarding and flooding only reach ports of the same VLAN.
  • Mirroring: swctl mirror 3 7 sends a copy of everything on port 3 to a sniffer on port 7. Mirroring must not slow port 3: copy into port 7's queue, so the bounded-queue rule from slide 06 applies again.

/* main(), BEFORE creating any thread */
sigset_t set;
sigemptyset(&set);
sigaddset(&set, SIGINT);
sigaddset(&set, SIGHUP);
sigaddset(&set, SIGUSR1);
pthread_sigmask(SIG_BLOCK, &set, NULL);
/* every thread created now inherits the mask */
/* the signal thread */
for (;;) {
    int sig;
    sigwait(&set, &sig);
    if (sig == SIGINT)  start_shutdown();
    if (sig == SIGHUP)  reload_config();
    if (sig == SIGUSR1) dump_mac_table();
}

In Lab 07 you wrote signal handlers. Here there are no handlers: the signal thread receives the signal as a normal function return, so it may lock mutexes and call anything.

14

Live reconfiguration and the lock order

Tier 2 · item 10, the hardest

swctl shutdown 3 while traffic flows

  1. Mark port 3 down, so no receiver queues new frames for it.
  2. Set closing and broadcast its condition variable, so a sleeping sender wakes up.
  3. Drop the frames still in its queue (each one: lower its refcount).
  4. Call shutdown() on the socket, so the blocked read() in the receiver returns.
  5. Join both threads, free the port, and sem_post the free-port semaphore.

A lock order (example)

Commands like "clear mac" or "vlan 3 20" take several locks. If two threads take them in different orders, they can deadlock. Pick one order, write it in the report, and follow it everywhere:

  1. the port table lock
  2. port locks, lowest port number first
  3. MAC bucket locks, lowest bucket first
  4. the stats mutex, always last
15

Bonus: two switches joined by a trunk

Tier 3 · beyond full marks
  • Two switches: this is the two-pipe channel from Lab 05 (section 3.5, two_way.c). Each switch treats its end as its trunk port. Host ..:0A reaches ..:0C on the same VLAN, and each switch learns the other's hosts as "behind the trunk".
  • Supervisor: a parent process restarts the switch when it crashes (fork, waitpid); the MAC table survives in shared memory.
  • Benchmark: a load generator and a graph: one global lock, striped locks, a read-write lock.
16

Sockets in one slide

New this project

A socket is a file descriptor that connects two processes, maybe on two machines. After the setup you use plain read() and write(), as with a pipe, but in both directions.

Server: the switch

int s = socket(AF_INET, SOCK_STREAM, 0);
bind(s, (struct sockaddr *)&addr, sizeof addr);
listen(s, 16);
for (;;) {
    int c = accept(s, NULL, NULL);
    /* c is one host = one port */
}

Client: a host

int s = socket(AF_INET, SOCK_STREAM, 0);
connect(s, (struct sockaddr *)&addr, sizeof addr);
write(s, frame, 17 + len);
read_full(s, header, 17);
  • TCP (AF_INET) for hosts: an address and port, like 127.0.0.1:9000.
  • UNIX domain (AF_UNIX) for swctl: the address is a file path. Same calls, local only.
  • Set SO_REUSEADDR on the server, or after a crash bind() fails for a minute with "Address already in use".

The tools we mark with

New this project

valgrind: memory errors

Runs your program on a simulated CPU and checks every memory access. Finds use-after-free, double free, leaks. Slow (20 to 50 times), so use small tests.

valgrind --leak-check=full ./switch 9000 8

Invalid read of size 1
   by send_to_port (leak.c:20)
 Address ... inside a block of size 68 free'd
   by unref (leak.c:15)
definitely lost: 68 bytes in 1 blocks

ThreadSanitizer: data races

A compiler option. Reports two threads touching the same memory without a lock, even when the run gave the right answer. Build a separate binary for it.

gcc ... -fsanitize=thread -pthread \
    race.c -o race_tsan
./race_tsan

WARNING: ThreadSanitizer: data race
  Location is global 'counter'
SUMMARY: ... race.c:12 in worker

gdb with threads (Lab 08)

gdb -p $(pidof switch)       # attach to a stuck switch
(gdb) info threads
(gdb) thread apply all bt    # who waits on which lock?

Watching from outside

ps -T -p $(pidof switch)   # its threads
ss -tnp                    # TCP connections
ss -xlp                    # UNIX sockets
ls -l /dev/shm             # shared memory
kill -HUP $(pidof switch)  # send a signal

Do not run the ThreadSanitizer binary under valgrind: use one tool per run, on two separate builds.

Rules

  • gcc -std=c11 -Wall -Wextra -Werror -g -O0, your own Makefile.
  • Clean under ThreadSanitizer and valgrind. We run both.
  • No busy waiting: while (!flag); or sleep() used to wait for another thread loses marks.
  • Check every call that can fail.

Hand in

  • All source files and the Makefile.
  • A README: how to build and run, and your config file format.
  • The report: thread diagram, every lock and what it protects, your lock order, one real bug and how you found it.
  • Which Tier 2 and Tier 3 items you did.

Marking is mostly automatic: public tests (forwarding, broadcast) you can run yourself, and hidden tests with slow hosts, crashing hosts, many hosts at once, and admin commands and signals during traffic.

Where to start

A build order that works
  1. Frames over TCP. A switch that accepts one host and prints every frame it reads. Write your host program at the same time. Test partial reads.
  2. Flooding. Several hosts; every frame goes to every other port. One receiver thread per port.
  3. Queues and senders. Bounded queue plus sender per port. Test with a host that stops reading.
  4. Refcounts, then the MAC table. Broadcast without copies; learning, lookup, aging.
  5. Port semaphore and clean SIGINT shutdown. Run valgrind and ThreadSanitizer now, not at the end.
  6. Tier 2, one item at a time, each followed by a ThreadSanitizer run.

Keep a note of every bug you hit while you go. One of them goes in the report.
